# Post-Mortem: CoreDNS Timeouts Cause Intermittent Gateway Failures

## Service Overview

- **Incident date:** 2026-02-27, 18:05-18:52 UTC (47 minutes)
- **Affected services:** APIGateway (Node.js), which resolves internal service names on every new upstream connection, and CoreDNS, the cluster DNS server (2 replicas in `kube-system`).
- **Impact:** About 4% of API requests failed with HTTP 502 during an evening marketing campaign. Failures were spread randomly across all upstream services.

## Common Error Signatures

### DNS Lookup Timeouts in the Gateway

```text
Error: getaddrinfo EAI_AGAIN auth-service.identity.svc.cluster.local
    at GetAddrInfoReqWrap.onlookup [as oncomplete] (node:dns:107:26)
    at APIGateway.proxy.connectUpstream()
```

- **Observed:** CoreDNS pods were at their CPU limit during the whole incident.
- **Observed:** Errors affected all upstreams equally, which pointed to a shared dependency rather than a single failing service.

## Root Cause Analysis

### CoreDNS Under-Provisioned for Query Volume

Traffic tripled during the campaign. CoreDNS still ran with 2 replicas and a CPU limit of 100m each, sized years earlier. CPU throttling made CoreDNS answer slowly, and lookups exceeded the client's timeout, producing `EAI_AGAIN` (temporary DNS failure).

How it was confirmed:

```bash
kubectl top pods -n kube-system -l k8s-app=kube-dns
kubectl logs -n kube-system -l k8s-app=kube-dns --tail=100
```

### Query Amplification from ndots:5

Pods use the Kubernetes default `ndots:5`, so a name with fewer than 5 dots is first tried with every search domain. Each lookup of an external name, such as the payment provider's API, generated up to 5 failed queries before the correct one. This multiplied the load on CoreDNS. APIGateway also had no DNS caching, so it repeated these lookups for every new connection.

## Playbook Remediation

### Immediate Mitigation

1. CoreDNS was scaled out, which ended the errors within 3 minutes:

   ```bash
   kubectl scale deployment coredns -n kube-system --replicas=6
   ```

### Follow-up Actions

1. Raise CoreDNS CPU limits and enable autoscaling for it based on cluster size.
2. Deploy NodeLocal DNSCache, so most lookups are answered by a cache on each node.
3. Set `dnsConfig.options: ndots: "2"` on APIGateway, and use fully qualified names with a trailing dot for external hosts.
4. Enable DNS result caching and connection reuse (keep-alive) in APIGateway.
5. Alert on CoreDNS CPU throttling and on the rate of `EAI_AGAIN` errors.
